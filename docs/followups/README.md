# Follow-ups

Changes we have found but not built yet. Each file groups follow-ups by area.

**How to use this folder**

- Add an item when you notice something during a review or demo. Say what is wrong, why it
  matters and where in the code it lives.
- Give it a **When**: `Now` (this sprint), `Sprint N`, or `After demo`.
- When an item is picked up, move it into `docs/backlog.csv` with a story ID and owner,
  then mark it here as `Moved to <ID>`.
- Items that change `docs/contracts.md` or `backend/app/models/` need the usual two reviewers.
